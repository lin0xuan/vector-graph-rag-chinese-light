# 文档切分方案

TXT、Markdown、DOCX 和 PDF 各自解析为带标题路径的结构块，然后交给同一个切分器。切分器只根据结构、位置和 token 预算决定边界。

```text
原始文档 → 格式解析与归一化 → 结构块 IR → token 切分 → 原文与关系索引
```

## 解析与归一化

| 格式 | 解析方式 |
|---|---|
| TXT | 尝试 UTF-8、UTF-8 BOM、GB18030、GBK、Big5，最后用 chardet 探测。拒绝包含替换字符或异常控制字符的结果。空行分段，序号和短行用于推断标题、列表和引用。短行可能是正文折行，结合上下文判断。 |
| Markdown | 用 markdown-it-py 的语法树识别标题、段落、列表、表格、引用、代码和 HTML。正文保留图片 alt 和链接文字，代码保留围栏及语言标记。代码和 HTML 保留原文内容，换行统一为 LF。 |
| DOCX | 直接读 OOXML。按样式和大纲级别识别标题，按 numbering 还原列表层级和编号。表格转 Markdown，横向与纵向合并单元格展开填充。保留文本框、图片替代文字、插入修订和脚注正文，丢弃删除修订、批注和页眉页脚。 |
| PDF | pdfplumber 提取带坐标的文字和表格，按行和栏重排，页码和可取得的边框写入元数据。去除跨页重复页眉页脚、页码和低透明度的大字号水印。根据字号和粗体识别标题，支持中文断行、英文连字符和跨页续段。表格优先使用线框检测，规则对齐的无框表使用对齐启发式。 |

文本统一换行、全角空格和零宽字符。正文压缩连续空行，并修复缺句末标点的中文折行。PDF 额外清除汉字之间的复制空格。Markdown 先保留块结构，正文修复只作用于段落，避免影响代码、表格和 HTML。

### PDF 扫描页与复杂版面

PDF 解析依赖可用以下命令安装。

```sh
pip install -e '.[documents]'
```

每页单独检测文本层。有效文字不足 50 字符时，扫描页以 300 DPI 渲染后交给 OCR。环境已安装 PaddleOCR 3 和对应推理引擎时优先用中文 PaddleOCR，其次使用 PATH 上的 Tesseract。Tesseract 需要 `chi_sim` 和 `eng` 语言数据。可用 `tesseract --list-langs` 检查。混合 PDF 只有稀疏文本页需要 OCR，解析错误会标出页码，整次导入在索引发布前停止。

常规一栏和双栏使用坐标规则。论文、报纸或幻灯片等复杂版面，可在安装 PaddleOCR 版面依赖后设置 `VGRAG_PDF_LAYOUT=pp-structure`，由 PP-StructureV3 提供阅读顺序、表格、公式文本和图注。版面模型的结果取决于模型版本。 [PaddleOCR OCR 文档](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html) · [PP-StructureV3 文档](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PP-StructureV3.html)

## 统一切分规则

1. 优先合并同一标题路径下的相邻短段。用中文 BGE-small tokenizer 计数，目标 384 token，通常在 256–512 token 范围内。文档标题和特殊 token 从 512 token 的嵌入预算中扣除。
2. 长段按句子回退。中文标点后的闭引号、括号留在前句，英文小数、常见缩写、版本号和 `Node.js` 这类名称保留在句内。
3. 单句超预算时按字符窗口切分并记录警告。窗口仍按真实 token 数控制大小。
4. 正文块以目标长度的 12% 为重叠预算。只带入能放进预算的完整句尾，标题、原子块和不相连的页面形成边界。
5. 代码、HTML、引用和列表项保持完整。长表按数据行切分，每块重复表头。单个原子块或单行加表头本身超过预算时保留完整内容并记录警告。原文向量会对超长原子块的各个 token 窗口编码并合并，引用仍返回完整块。

## 元数据与重建

| 字段 | 含义 |
|---|---|
| `heading_path`、`block_type`、`source_type` | 标题路径、块类型、原始格式 |
| `start_offset`、`end_offset` | 从 0 开始的字符位置，区间左闭右开。TXT 和 Markdown 指向解码后的输入，保留换行修复前的字符位置。DOCX 和 PDF 指向解析后、归一化前的阅读顺序文本流 |
| `page_no`、`end_page_no` | PDF 起始页码和可选的结束页码，其余格式的 `page_no` 为空 |
| `bbox`、`page_bboxes` | 可取得的 PDF 坐标，采用页面左上为原点。多页片段另附各页边框 |
| `token_count` | 片段正文实际 token 数，包含重复表头，不计文件标题 |

重叠片段各自带原文区间。长表分片的区间指向该片的数据行，重复表头可在同一张表的首段定位。PDF 的边框定位到原结构块，句子级切分会沿用这个边框。

旧索引仍可查询。沿用原 `source` 重新导入后，新片段和关系索引会替换该来源的已发布版本。正式 A/B 使用新数据目录和新输出，切分版本会进入评测清单，防止把旧索引和新切分混用。

## 实现入口

- [documents.py](../src/vector_graph_rag_chinese_light/documents.py) 的 `parse_file` 和 `parse_text` 负责解析和生成带偏移的结构块。
- [docx_parser.py](../src/vector_graph_rag_chinese_light/docx_parser.py) 与 [pdf_parser.py](../src/vector_graph_rag_chinese_light/pdf_parser.py) 负责格式专有结构和坐标。
- [splitter.py](../src/vector_graph_rag_chinese_light/splitter.py) 的 `split_blocks` 负责 token 预算、边界、重叠和片段元数据。
- [rag.py](../src/vector_graph_rag_chinese_light/rag.py) 接入实际 BGE tokenizer、原文向量和关系建索引，[index.py](../src/vector_graph_rag_chinese_light/index.py) 保存引用元数据。
